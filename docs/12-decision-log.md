| D-036 | **Phase 1 engineering decisions (Node services).** (1) **Node 24 LTS** (exact patch at least 14 days old); Node 26 is revisited after it enters LTS on 2026-10-28. (2) Build on `node:24-bookworm-slim`, run on `gcr.io/distroless/nodejs24-debian13:nonroot`, both pinned by digest; the health probe is a `node` script (no shell in the runtime image). (3) **Independent per-service npm packages** with their own lockfile, no workspaces; `services/_template/` is the copy source. (4) **npm only**, hardened by a committed per-service `.npmrc`: `min-release-age=7`, `ignore-scripts=true`, `save-exact=true`, `engine-strict=true`; `npm ci` in CI and Docker; npm 11.10 or newer is required because older versions silently ignore the setting. (5) TypeScript strict, ESM, `tsc` build to `dist/`. (6) ESLint (flat config, typescript-eslint), Prettier, Vitest, Supertest, Testcontainers, 60% coverage gate on core logic. (7) Libraries: Fastify, Zod, `fastify-type-provider-zod`, `@fastify/swagger`, pino, `pg`, Drizzle ORM with plain SQL migrations (stable releases only; the latest stable 0.x if no stable 1.x exists), `rabbitmq-client` (`amqplib` 0.10.7 or newer as the fallback); exact versions pinned. (8) **No cross-run Docker build cache in CI yet** (plain `docker build`, no extra actions); revisit when a build exceeds about 5 minutes. (9) **Event envelope** with exactly six fields (`eventId`, `eventType`, `version`, `occurredAt`, `correlationId`, `payload`); the JSON Schemas in `contracts/events/` are the source of truth. (10) **RabbitMQ topology:** topic exchange `civic.events`, one quorum queue per consumer, dead-letter exchange `civic.dlx` with a DLQ per queue, delivery limit, publisher confirms, manual acks; details in `contracts/events/README.md`. (11) **Outbox relay:** a polling loop with `FOR UPDATE SKIP LOCKED` every 500 ms; consumers keep a `processed_events` inbox table. (12) **Errors** use RFC 9457 problem details plus `code`, `correlationId` and `errors`; header `x-correlation-id`, logged as `correlation_id`. (13) **Database provisioning:** an idempotent one-shot `db-init` Compose service creates the `civic_<service>` databases and roles; migrations run through `node dist/migrate.js`. Verified 2026-10-11: Node 24 is Active LTS until 2026-10-20 and supported until 2028-04-30, distroless Node 24 images exist, `rabbitmq-client` and `fastify-type-provider-zod` with `@fastify/swagger` are current, and npm supply-chain incidents in 2026 (axios on 2026-03-31, keyv on 2026-08-04, the latter with valid provenance) make release-age cooldowns and blocked install scripts mandatory | Node 26; pnpm; npm workspaces; `amqplib`; classic queues; LISTEN/NOTIFY or CDC for the outbox; a per-run Docker cache | Fewest new tools, strongest supply-chain posture, and each choice settles a deferred row in `04`, `05` or `03` | Approved | 03, 04, 05, 08, contracts, PROGRESS |

| D-038 | **Auth service design and Slice 2 implementation.** (1) **EdDSA (Ed25519)** access tokens with `jose`, claims sub, role, iss "civic-auth", aud "civic-api", iat, exp (15 minutes), jti, header kid; the private key comes from the env var `JWT_PRIVATE_KEY_B64` (base64 of a PKCS8 PEM), generated by `init-env.ps1` with the digest-pinned Node image; a public JWKS endpoint (`/.well-known/jwks.json`); every service verifies with the public key (SEC-02). (2) **Opaque refresh tokens**: 32 random bytes, only their SHA-256 hash stored, 7-day lifetime, rotated on every use, token families, reuse of a revoked token revokes the whole family, returned in the JSON body for now (httpOnly cookie considered later with the frontend). (3) **argon2id** with parameters from config (default 19456 KiB memory, 2 iterations, parallelism 1), PHC string format, built-in `crypto.argon2` if stable on Node 24 else `@node-rs/argon2`; password policy 10-128 characters. (4) Plain-SQL migrations applied by `node dist/migrate.js` (checksums, advisory lock) and Drizzle ORM for queries. (5) Service builds use the **repository root as Docker build context** (`docker build -f services/<svc>/Dockerfile --build-arg SERVICE=<svc> .`) with a `Dockerfile.dockerignore` per service, so event schemas from `contracts/events/` are copied into the runtime image; producers validate events with Ajv before writing the outbox. (6) Liveness and readiness are separate: the HTTP server starts first, dependencies connect in the background with backoff, `/healthz` is always 200 once running, `/readyz` needs the database and RabbitMQ. (7) Integration tests use Testcontainers with the same digest-pinned images as Compose. (8) The committed `contracts/openapi/auth.v1.openapi.json` must equal the generated spec (drift test). Dependabot: the `/services/_template` entries are removed (the template is refreshed manually) and semver-major updates are ignored for npm, docker and docker-compose entries; major upgrades are manual decisions. | RS256; refresh tokens in cookies; JWTs without rotation; per-service contract copies; Testcontainers-free tests; automated major version updates | Ed25519 produces compact, fast, secure signatures without key size overhead; token rotation limits exposure window; root build context preserves contract single source of truth without monorepo build tools; manual major bumps avoid unplanned breaking shifts | Approved | 03, 04, 05, 08, contracts, PROGRESS |
